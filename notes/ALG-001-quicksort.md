# ALG-001 — Quicksort

## Why it matters

This paper introduced the definitive 1962 presentation of Quicksort, one of the most influential sorting algorithms in computer science. Quicksort combines an in-place partitioning procedure with recursive divide-and-conquer, giving excellent practical performance, low auxiliary-space requirements, and a design whose constant factors made it exceptionally competitive on real machines.

Its importance goes beyond sorting. The paper is a compact example of algorithm engineering: the author discusses not only the high-level idea, but also implementation details, inner-loop structure, storage cost, and empirical performance.

## Key ideas

1. **Partition around a pivot** — rearrange the array so that smaller elements lie on one side and larger elements on the other.
2. **Divide and conquer** — after partitioning, the two resulting regions can be sorted independently.
3. **In-place operation** — partitioning requires very little extra storage compared with merge-based methods.
4. **Average-case efficiency matters in practice** — the algorithm can be extremely fast despite a quadratic worst case.
5. **Implementation details affect algorithmic performance** — loop structure, pivot choice, recursion strategy, and small-partition handling materially influence real execution time.

## Recommended reading approach

**Read fully.** The paper is short and unusually useful as both an algorithms paper and an algorithm-engineering paper.

### Section-by-section guide

- **Opening description:** Understand the problem setup and the two-sided scanning partition procedure.
- **Partition method:** Read carefully. Track the left and right scanning indices and what invariant is preserved after each exchange.
- **Recursive sorting procedure:** Connect the partition result to divide-and-conquer recursion.
- **Storage and implementation discussion:** Pay attention to stack usage and the practical implications of recursion depth.
- **Refinements and optimization:** Read closely. These sections show how algorithmic ideas are adapted to machine realities.
- **Performance discussion:** Compare the empirical claims with the theoretical average-case and worst-case behavior you know today.

## Practical connection to Linux and packet-processing work

Quicksort is not specifically a networking or eBPF paper, so the connection is broader systems engineering rather than domain-specific.

The useful lesson is that asymptotic complexity is only part of performance. In Linux datapath or observability code, two algorithms with the same big-O complexity can behave very differently because of cache locality, branch prediction, memory traffic, allocation behavior, and constant factors. Hoare's paper is an early, clear example of treating an algorithm as something that must perform well on an actual machine, not merely satisfy a mathematical bound.

For performance debugging, this suggests measuring both the algorithmic shape and the machine-level costs generated by the implementation.
